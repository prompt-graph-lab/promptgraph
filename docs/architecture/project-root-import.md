# Safe Existing Project Import into Project Root

Status: **implemented for Pro v1**.

`Import Existing Project into Project Root` is the Project Management migration path for older Projects stored outside the effective Project root. It creates a safe copy under `<effective-project-root>/<destination-name>/`; it never moves, deletes, overwrites, or merges the source directory. The source may come from the currently open external Project, an external Recent Project, or an authoritative manual Project JSON path. Current-Project import reads the last saved disk state and does not trigger Quick Save or copy unsaved session changes.

## Preview and commit contract

Recursive filesystem work runs only on explicit Preview and again as authoritative Apply revalidation. Preview validates the primary Project through the existing loader and graph builder, inventories regular files in stable natural order, reports byte/file/Project/Fork counts and path classifications, and blocks source or child symlinks, junctions/reparse points, root escapes, duplicate resolved paths, unsafe destination names, and case-insensitive destination conflicts. `.git`, `.promptgraph_cache`, `__pycache__`, `.pytest_cache`, `.mypy_cache`, `.DS_Store`, and `Thumbs.db` are ignored; an ignored directory name is never traversed even when that entry is a cache symlink. Project data such as `refs/`, `candidates/`, `generated/`, `routes/`, `exports/`, `workflows/`, and `forks/` remains copy data.

The Preview signature covers normalized source/destination identity, the primary Project digest, inventory paths plus regular-file size/mtime, Project/Fork JSON digests, ignored entries, planned internal/external path treatment, and each supported Fork manifest's resolved source/Fork/manifest relationship. Apply rebuilds that Preview and fails stale before copying when the signature differs. Files are copied with `copy2` into a hidden `.promptgraph-import-*` staging directory below the Project root. JSON is parsed only from bytes matching the planned digest, and the complete inventory is checked again immediately before commit so additions, removals, and stat changes during staging fail stale. Rewritten staged Projects and supported Fork manifests are validated before a bounded Windows-aware atomic directory rename. Failure cleans staging and leaves no partial final destination; the original Project directory and bytes are unchanged.

## JSON and path compatibility

Migration edits deep-copied raw JSON rather than round-tripping through the Project dataclass. Only fields in the explicit Project and Fork path registries are considered. Relative Project-local paths remain relative. Internal absolute paths are rebased to destination-relative values where the runtime supports Project-relative resolution, or to destination absolute values for absolute-only metadata. External absolute dependencies are retained unchanged and reported as warnings. Unknown fields, prompt/negative text, notes, workflows, export/settings JSON, and arbitrary strings are never searched or replaced.

All valid PromptGraph Project JSON files directly below the source directory are preserved and rebased; the selected JSON remains primary. Preview builds a normalized, case-normalized source-to-destination mapping for those direct Project JSONs. Known `forks/<name>/project.json` Projects are also rebased. Each supported Lightweight Fork manifest must map its `source_project_path` to one of those valid direct Project plans and must identify its actual sibling `project.json` and `manifest.json`; an unmappable source or stale destination relationship is a Preview blocker. Valid manifests carry their own expected mapped source/Fork/manifest paths into staged validation instead of inheriting the selected primary JSON. Registered source/destination/materialized-entry paths, including Append history, are then rewritten so same-source Append validation remains compatible after import. Malformed or unsupported manifests are copied unchanged with warnings rather than generically migrated. No Project, PromptLine, Recent, or Fork manifest schema changes are introduced.

## Session and discovery ownership

The UI has one owner: `render_existing_project_import_section()` in Project Management, after Project Defaults, New Project, and Duplicate Project. Preview and source/destination inputs are session-only and survive Back/reopen; the confirmation checkbox and phrase are always cleared by Back or a successful Project transition. Apply requires a confirmation checkbox and the exact `COPY PROJECT` phrase. Only successful commit adds the imported primary JSON to Recent Projects with `update_last_project=False` and requests a Project Directory Browser refresh. It does not auto-open the result, replace the current Project, add history, or mutate Gallery/Module/ComfyUI state. `取り込んだProjectを開く` is a separate explicit action through the existing authoritative Project loader.

This operation is not Duplicate Project, Save As, Project Assets localization, Lightweight Fork creation, external-asset packaging, source cleanup, or a generic schema migration.
