# PromptGraph Pro 1.0.0

PromptGraph Pro 1.0.0 is the public open-source release defined by a vetted
clean source tree. This document records the release content and compatibility
boundaries; publication-channel metadata and provenance records travel with the
selected release candidate.

## What this release is

PromptGraph Pro 1.0.0 is a Gallery-first Windows workspace for building and
reviewing image/prompt sequences around Stable Diffusion and ComfyUI-style
generation. It keeps images, editable prompts, Candidates, sequence structure,
and reusable prompt Modules visible as one production workflow while leaving
adoption, destructive operations, save, and export under explicit user control.

Project creation, open, save, duplicate, and import are supported. Projects are
external user data: the application source/release package does not contain
Projects or move them into the application directory.

## Main workflows

- Create a Project, open normal or recent Projects, Quick Save, Save As,
  duplicate a complete Project directory, or safely copy an existing valid
  Project directory into the configured Project root.
- Import prompt text or metadata-aware PNG and JPEG files, recover positive and
  negative prompt information where supported, and retain source/workflow
  metadata separately from editable prompt text.
- Review and edit Illustration cards in Gallery, organize them into Scenes, and
  use Selected Scenes or other operation-owned scopes for generation and batch
  work.
- Inspect sequence structure in Prompt Graph and PromptCloud, then use Graph
  Edit, Focus Edit, and preview-first batch operations for controlled changes.
- Review the resolved main-image order in Sequence Preview before Final Images
  Export.

## Project and Gallery

Gallery is the primary production surface. Inline positive/negative prompt
editing stays beside the current Illustration image. Scene separators,
collapse/color controls, Illustration reorder, Trash and restore, and scoped
generation help manage longer sequences without changing the meaning of the
underlying Project JSON.

Generated images enter a Candidate pool first. They do not silently replace an
existing reference/main image or enter the final sequence. Explicit adoption
can set a main image for an image-less Illustration, swap a Candidate with the
current main image while retaining the old main image as retreat history, or
insert a useful Candidate as another Illustration.

## Candidates, Variants, and Workbench

Candidates store generated or manually registered alternatives for an
Illustration. Candidate image adoption and Candidate prompt adoption are
separate operations. Variants retain close alternates and lineage metadata
where available. A Workbench card provides per-Illustration scratch generation
and review outside the normal graph, batch, Scene-wide generation, and Final
Export target set.

Project Assets can copy external Candidate/Variant files into the Project after
a read-only capacity preview and explicit confirmation. Verified duplicate
cleanup is a separate destructive operation with stale checks; it does not
create version history or replace normal backup.

## Scene and sequence management

Scenes are separator-bounded Illustration groups. Users can add separators,
create alternate Scenes, collapse/color Scene groups, move Illustrations, and
target supported operations by current, selected, or all Scenes.

Sequence Snapshots preserve exercised sequence and selected/generated image
choices for compare/apply workflows. Sequence Storyboard supports visual
review. Trash and restore remove/reinstate records without deleting linked
source image files. Sequence Preview is read-only and shows the same resolved
main-image ordering used by Final Images Export.

## Graph Edit and batch editing

Graph Edit combines Prompt Graph, PromptCloud, a paged Illustration Browser,
Batch Editing, selected-token operations, and reorder tools. Its Browser is a
session-only display control; the graph, saves, batch operations, and export
continue to use the complete Project.

Batch tools preview exact token add/replace/remove, formatting cleanup, weight
normalization, duplicate removal, and propagation before apply. Operation Scope
presentation explains which operation-owned targets consume Selected Scenes.

## Module and Attribute workflows

Project Modules store reusable prompt bodies and Module Graph metadata. Users
can create/edit Modules, scan matching Illustrations, preview replacement with
`<mod:name>` references, insert saved references, toggle referenced Modules,
and preview Module Swap. Attribute Groups and Attribute Labels are manual
project metadata used by authoring, inspection, and preview-first swap flows.

The Global Module Library is a separate reusable user library. Explicit copies
move normalized Module records between it and the current Project Module
Library; there is no live synchronization, inheritance, dependency manager,
version history, or remote repository. Local AnimaDex records can be discovered,
previewed, and explicitly imported as Global Modules.

## ComfyUI and metadata workflows

ComfyUI is external and optional except for generation. Generation runs only
after an explicit user action against a configured compatible endpoint and
workflow. Gallery and Focus Edit retain execution; ComfyUI Settings provides
read-only workflow analysis, prompt/LoRA export helpers, Negative Prompt
Consistency, Global Negative/Delta Preview, and Generation Settings
Consistency.

Metadata-aware PNG and JPEG import recognizes exercised A1111/Forge,
NovelAI EXIF, and ComfyUI metadata shapes. Raw workflow JSON is kept out of
positive prompt editors unless prompt text can be extracted safely.

## Preview and Final Export

Final Images Export writes new ordered copies below the Project's
`exports/final` root, normally in a timestamped subdirectory. It skips
non-exportable records and can strip PNG metadata from exported copies only;
source images and Project-linked files are not deleted or rewritten.

The portable Final Export manifest v2 uses `manifest_version: 2` and
`path_contract: portable-relative-v1`. Output references are manifest-relative,
Project-local provenance is Project-relative, and external provenance is
reduced to a filename. Prompt and Scene text remain user-authored content, so
the manifest is portable but not anonymized.

## Data compatibility

Current Pro 1.0.0 Project JSON written by the current atomic writer reopens in
Pro 1.0.0. Loader defaults and normalization cover the older/minimal synthetic
shape exercised by `tests/fixtures/release/legacy_project_minimal.json`: absent
Project metadata and Sequence Snapshots, a missing negative prompt, a legacy
flat Module entry, relative Unicode image paths, and one normal Illustration.
The fixture is loaded, graph-rebuilt, saved to a new path, and reopened.

This is a bounded compatibility statement, not a guarantee for every past,
future, or extension schema. A load-and-save can normalize current fields;
unknown top-level or PromptLine extension fields are not guaranteed to survive.
Back up untested Projects before first open and save.

The exercised Global Module fixture covers the accepted legacy
`{"module_library": {...}}` wrapper, a flat string Module body, a current nested
Module Graph record, Unicode, normalization, metadata preservation, atomic
save/reopen, and malformed-file fail-soft behavior.

See the [backup, upgrade, rollback, and recovery guide](../backup-upgrade-rollback.md)
for the operational contract.

## Known limitations

- The supported release target is public source on Windows 11 x64 requiring
  CPython 3.14.x. Python, an installer, and ComfyUI are not bundled.
- Current stable Edge and Chrome are the validated browsers.
- There is no automatic backup, Project version history, rollback, cloud
  synchronization, or recovery wizard. There is no automatic migration or repair.
- Arbitrary future/unknown Project and Global Module Library shapes are not
  guaranteed. Unknown extension fields are not guaranteed to round-trip.
- Global Modules have no live sync, versioning, or inheritance.
- Settings are per extracted application directory and may contain stale
  machine-specific absolute paths.
- External absolute asset paths are machine-specific. Project portability is
  strongest for Project-relative linked assets. A Project directory alone is
  only a partial backup when Project JSON still references main/source images,
  workflows, or other required assets outside it; those external assets must be
  backed up and restored separately. PromptGraph does not automatically collect
  or relink arbitrary external assets.
- Final Export is derived output, not a Project backup. Metadata stripping
  changes exported copies only.
- Prompt/image alignment still requires human review.
- Final UI, browser, DPI, disposable ComfyUI, documentation, backup/rollback,
  public-tree exposure, and exact-public-candidate verification remain mandatory
  in release-candidate QA. Archive checks apply only if a convenience archive
  is selected.

## Supported environment

The supported contract is Windows 11 x64, CPython 3.14.x x64, the exact locked
runtime in a Project-local `.venv`, and current stable Edge or Chrome. See
[Supported Environment](../supported-environment.md) for exact setup, browser,
dependency, and ComfyUI boundaries.

## Distribution and integrity

The primary distribution is a clean public Git source repository. Its bootstrap
records the reviewed candidate SHA and the distinct public bootstrap SHA, and
verifies the selected file tree through a reviewed inventory/hash comparison.

A deterministic convenience archive may be offered only if the separate
neutral-tooling review selects one. The former FANBOX-specific builder remains
historical distribution infrastructure and is excluded from the source-only OSS
tree. See the current [public OSS release process](../release-process.md).

The public source tree uses the standard [MIT License](../../LICENSE)
for PromptGraph-authored source code, documentation, and synthetic examples or
fixtures, with Copyright (c) 2026 PromptGraph Lab. Runtime dependencies are
installed separately from `requirements.txt` and are not vendored into the
source tree. The [license and attribution audit](../release-process.md#license-and-attribution-audit)
records the dependency, content-provenance, and notice-file conclusions. The
the public-tree exposure gate, clean-repository bootstrap, and release-candidate
QA each retain their separate responsibilities.

## Backup and upgrade

Before opening important data in a new version, back up the complete Project
directory, every required asset referenced outside it, and resolved
`global_modules.json`. Keep the previous application directory, obtain the new
official public source/release package in a separate directory, create a fresh
`.venv` with that version's `setup.bat`, and first open a backup copy or
non-critical Project. Rollback uses
the previous application directory plus pre-upgrade Project, external-asset,
and Global Library backups; it is not a downgrade-compatibility promise.

## Privacy and security

Projects and backups may contain prompts, negative prompts, generation
metadata, workflow information, model/LoRA names, filenames, absolute paths,
notes, and images. Inspect them before public upload. Final Export metadata
stripping does not sanitize Project JSON or backups, and SHA-256 detects byte
changes but is not an identity/signature system by itself.

## Human validation boundary

Automated compatibility and archive rehearsals do not replace release-candidate
QA. The
exact reviewed public candidate tree still requires independent supported-Windows
installation from its public instructions, normal browser/DPI/UI review,
Gallery/Graph Edit workflows,
disposable ComfyUI generation, prompt/image alignment review, backup/upgrade/
rollback rehearsal, documentation/screenshot checks, checksum/metadata review,
and final known-limitations approval. If a convenience archive is selected,
the exact archive also requires checksum, provenance, extraction, setup, launch,
and byte-identity validation.
